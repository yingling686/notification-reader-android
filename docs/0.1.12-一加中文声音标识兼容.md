# 听讯 0.1.12 一加中文声音标识兼容

2026-10-23，versionCode 13，原签名，配置及数据库不变。

## 根因证据

朋友 OnePlus PLC110 / Android 16 的完整精简诊断显示：引擎 com.oplus.ttsaccessibilityengine 初始化成功，中文可用性返回 1。共有 5 个声音，其中“中文（明朗男声）”“中文（清冷女声）”“中文（温柔女声）”的 locale 均为 chn、networkRequired=false；两个英文声音为 usa。旧版只以 locale.language == zh 筛选中文，因此错误地报告 chineseCount=0、offlineChineseCount=0，并阻止合成。

这确定了“缺少离线中文语音包”的应用侧误判；不应继续要求朋友重复下载相同资源，也不能把该误判归因于 Android 16 整体限制。声音资源实际合成和蓝牙出声仍需修复后的实机试听。

该次 session.running=false、gateReason=SESSION_INACTIVE；需要回首页开启听读。recentBlockingEvent 中旧 HEADPHONES_MISSING 事件早于当前导出，不能作为当前耳机未连接的结论。通知访问、通知/电话权限已授予，监听已连接。

## 修复

新增统一 SystemVoicePolicy。保留所有引擎既有 zh 规则，仅对 com.oplus.ttsaccessibilityengine 增加 chn 中文别名。声音列表、合成时的候选筛选和诊断中文计数共用该规则；列表把已识别的 chn 显示为“中文”。

仍要求 networkRequired=false。其他引擎的 chn 不自动认作中文，usa/en 不通过筛选；没有按声音名称猜语言，没有允许联网声音或新增云端授权。保持原声音选择优先级、合成流程、耳机路由安全检查、队列与后台逻辑。

## 验证与边界

单元测试重放此次目录的 3 个 chn、2 个 usa，验证只接受前 3 个离线中文；检查网络声音被排除、别名限定引擎及其他引擎标准 zh 行为保留。保留既有系统 TTS、刷新、后台合成与诊断回归。最终结果见 delivery/测试记录-0.1.12.md。

无朋友的一加实机连接，尚未证明该引擎的文件合成及眼镜/耳机实际出声通过。修复的是已经确定的语言筛选错误，后续若有新的合成/路由错误，使用同版精简诊断继续定位。
