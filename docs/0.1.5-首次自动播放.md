# 0.1.5：开启一次，首条通知自动播放

## 目标与改动

用户在 Android 17 红米＋小米 AI 眼镜上反馈：免打扰关闭、听读未暂停，但锁屏需要点两次听讯媒体卡片的播放键，之后才能连续自动听。旧日志里的 `QUIET_HOURS` 只说明当时受到免打扰阻止，不能据此解释这一新现象。

此次不把按钮外观变化当作问题解决，分别调整与验证自动启动链路和媒体状态：

- 用户在可见 Activity 点击开启，服务注册媒体前台用途后确认启动。保存固定来源 `UI / NOTIFICATION / MEDIA / RESTORE / AUTOMATIC / SYSTEM`；新通知直接触发队列，不等待 `MediaSession.onPlay()`。
- 统一等待通知、合成中、播放中、用户暂停、受阻、已停止六种状态。只有实际准备或播放音频时激活媒体会话；等待通知时媒体会话不活动，常驻通知是普通服务通知，播完回到自动等待，不停止听读前台服务。
- 系统媒体状态先更新，再发布给首页和通知，避免界面已显示等待而媒体会话还活动的瞬间不一致。
- 开启、暂停、恢复操作幂等，暂停与恢复使用不同 PendingIntent。重复播放/恢复命令不重设会话开始时间、不取消正在处理的音频，也不会把已恢复的会话再暂停。
- 新消息入库前等待先前暂停/清空/设置操作的收尾；仍在写入时跨越取消边界的旧消息保持待确认。避免恢复后到达的新消息被旧暂停操作一起转为手动补读。
- 免打扰保持用户配置，生效时首页和通知显示截止时间。断连、通话、暂停和清空继续取消任务，旧积压仍由用户确认。没有静音音轨保活、没有新增全天唤醒锁、没有通过模拟点击播放获得系统授权。

诊断新增启动请求与确认、自动调度、媒体播放/暂停指令、恢复和状态变化；事件附当前听读状态、暂停/免打扰状态及启动来源。旧版事件允许缺少这些字段。仍保留最多 200 条、最长 24 小时，不保存通知正文、联系人、音频或密钥。

## 验证方式

保留此前单元与设备测试，新增等待状态与停止的区别、重复播放/恢复不中断当前任务、暂停积压与恢复后新消息的区分、暂停与恢复竞争下的新消息自动处理。

首次自动播放用例每个场景都重新开启会话；在首条通知之前不调用试听、`now()`、补读或媒体播放命令。覆盖直接回桌面、切到系统设置、立即锁屏、锁屏静置 10 秒后发首条通知；最后场景连续发送五条通知。验证真实默认中文 TTS、真实焦点申请和同应用进程中的真实 MediaPlayer 完成，播完回到等待状态、媒体会话不活动，常驻通知不含 MediaStyle。

真实播放器探针只在任务专用的 `-no-audio` 模拟器运行，使用固定中文测试消息。它替代的是硬件耳机检查，未替换 TTS、AudioManager 或 MediaPlayer；生产 APK 不含探针，生产耳机路由检查保持完整。因此它能检查平台后台音频调用，不能证明小米眼镜已实际出声。

Android 17 使用 API 37.0 Google APIs x86_64 系统镜像，应用仍以 compile/targetSdk 36 构建。首次自动播放测试尝试官方文档的 `set-enable-hardening` 和 AOSP Android 17 分支的 `set-hardening`，设置 `throw` 后必须从 `dumpsys audio` 确认 `mHardeningOverride=3`，启用对所有应用的严格后台音频限制和可抛错模式。本镜像的 `help` 和不支持的命令可能无输出并返回成功，因此不能只检查退出码。结束后恢复 `enable`，从不关闭限制来取得通过。检查测试区间新增的本应用 `AudioHardening` 拒绝记录。Android 15 / API 35 运行同样用例，但不调用 Android 17 专有命令。

## 手机上验收

覆盖安装后，打开听讯，选择“即时朗读＋系统机读”，连接眼镜并只点一次“开启耳机听读”。确认免打扰没有生效、没有暂停，然后直接回桌面或锁屏，在第一条通知前不要试听或点击任何媒体播放键。由另一设备发新消息，确认眼镜实际出声；再连续发五条、静置数分钟后再发一条。

仍有异常时，复现后复制后台诊断。检查 `START_REQUEST → SERVICE_FOREGROUND → START_ACK → AUTO_DISPATCH → TTS_BEGIN / TTS_DONE → FOCUS_RESULT → PLAYER_PREPARED → ROUTE_CONFIRMED → PLAY_DONE`，并对比是否出现 `MEDIA_PLAY_COMMAND`。`TTS_DONE` 或播放器完成本身都不能证明人耳已听到。

红米实机、眼镜真实输出、厂商后台冻结、长期 Doze、来电与断连无外放仍需实机验收。只有首次消息无需点击播放便实际从眼镜出声，才能确认用户的问题解决。强行停止或手机重启后仍需重新开启听读。

最终验证：52 项单元测试通过；Android 15 / API 35 的 21 项设备测试通过，0 失败、0 跳过；Debug / Release Lint 均 0 错误、27 项依赖版本、KTX、KSP 等建议。API 35 同样完成四个首次自动播放场景和锁屏五条连续通知。测试收尾在唤醒屏幕前先取消悬挂的合成，防止异常收尾触发二次断言掩盖最初失败；最终全量报告均已保存。

2026-10-18：Android 17 / API 37 全量 21 项设备测试通过，0 失败、0 跳过。首次自动播放分别重新开启四次会话，桌面 1 条、系统设置 1 条、立即锁屏 1 条、锁屏静置后连续 5 条均完成；没有媒体播放或手动播报操作。本镜像实际使用 `cmd audio set-hardening throw`，核验值为 3，测试结束保持 `enable`（值 2）；没有发现测试区间新增的本应用 AudioHardening 拒绝记录。构建指纹与固定测试标记保存在 `api37/`。
