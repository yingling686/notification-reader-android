# 0.1.3：后台与息屏即时听读

## 修复内容

此前新通知只写入数据库，随后靠每秒协程轮询启动播报；息屏后 CPU 休眠会让轮询延后，前台服务本身也不能代替 CPU 唤醒保护。

- 通知监听收到消息后直接触发即时队列。合成或播放中到达的下一条通知，在同一次处理会话内继续消费，不依赖界面刷新或“现在播报”。重复通知不会再次触发朗读。
- 接收通知时先获取最长 60 秒的部分唤醒锁，再启动异步解析、去重和入库。开始处理时接续获取任务唤醒锁，任务最长 10 分钟，保护锁最长 11 分钟；正常完成、失败和取消均释放。等待通知时不持锁，不点亮屏幕。
- MediaPlayer 增加 `PARTIAL_WAKE_LOCK` 播放保护；实际耳机路由检查、通话和断连停播继续生效。系统机读和两种云端语音共用该后台处理与播放路径。
- 用户开启的常驻前台服务改为 `START_STICKY`，允许 Android 在回收进程后重建会话；保存暂停选择，重建时保持暂停。进程重建前未完成的内容继续待确认，不自动重读。系统是否及何时重建由 Android 和厂商决定。
- 首页显示即时处理状态，新增后台运行、电池优化状态及设置入口；未选择任何应用时明确提示先选择应用。
- 沿用包名和签名，versionCode 4，可覆盖 0.1.2；数据格式、MiniMax 和 OpenAI 兼容配置保持兼容。

## 手机上的操作

1. 覆盖安装 `听讯-0.1.3.apk`，打开应用并检查通知访问、通知权限和电话状态权限。
2. 在“应用与规则”选微信等需要听的应用；首页选择“即时朗读”。
3. 红米 / HyperOS：通过首页“后台与息屏听读”打开听讯应用信息，允许后台运行，把电池策略设为“无限制”，开启后台自启动。具体名称以系统版本为准。电池优化显示已豁免，只说明 Android 的优化名单，不代表厂商全部后台策略已放行。
4. 连接小米 AI 眼镜，开启听读并试听。确认常驻通知存在、没有暂停；回到桌面并息屏，让另一台设备发送一条新微信消息。无需点击“现在播报”。
5. 断开眼镜应立即停止且不外放；重连只对新消息正常处理，旧积压由用户确认补读。

“即时”指通知到达手机并被系统交给听讯后自动开始处理。AI 合成需要等待网络和服务商响应；可先用系统机读验证后台行为。原应用未及时推送、锁屏隐藏正文、没有中文离线 TTS、通话中、免打扰或耳机不符合条件时无法立即读出。

定时模式仍使用会话内计时，深度休眠可能延迟定时触发；没有用全天唤醒锁保证短间隔。强行停止、手机重启和用户停止会话后，需要手动重新开启；不能绕过系统强行停止或厂商杀进程限制。

## 验证与实机边界

新增 Android 仪器测试将应用退到桌面、关闭屏幕，通过系统通知监听送入两条通知；第一条合成期间再发送第二条，检查自动处理、连续消费、去重、任务唤醒释放。使用模拟合成和模拟耳机播放器，不会向模拟器扬声器外放；该测试验证后台调度，不替代真实耳机声音验收。

另验证部分唤醒锁重复关闭安全、空闲不持锁，以及服务重建保留暂停、主动开启重置暂停。

2026-10-18 验证结果：42 项单元测试、Android 15 模拟器 14 项仪器测试全部通过。Debug / Release Lint 均无错误，23 项提示为依赖更新和 KTX/KSP 建议。签名 release 构建成功，0.1.2 → 0.1.3 覆盖安装成功，主页面冷启动成功。签名 SHA-256 与旧版本一致：`7cff9843bd8ac504cb1c54c7ca6163449cc7e0f74f652b721c0f4c2e54eff356`。原始报告保存在 `results/0.1.3/`。

暂停恢复测试验证保存与读取状态，未模拟真正的系统低内存杀进程；`START_STICKY` 重建时机仍待实机验证。息屏测试验证自动调度到模拟播放器，没有验证模拟器深度 Doze 或真实蓝牙输出。

红米 K90 Pro Max、小米 AI 眼镜的实际息屏出声、厂商省电、音乐/来电/断连无外放，以及真实 MiniMax / OpenAI 接口调用仍需实机验收。此次没有连接实机或使用用户云端密钥。

实现依据：[Android 官方后台 MediaPlayer 与唤醒锁说明](https://developer.android.com/media/platform/mediaplayer/background)。
