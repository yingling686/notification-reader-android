# 0.1.4：退后台不读的修复与诊断

## 已知现象与改动

用户在红米 K90 Pro Max＋小米 AI 眼镜上反馈：使用系统机读，回桌面即不朗读，听读常驻通知仍存在，重新打开界面后旧消息自动读出。没有连接该实机，因此此次不能直接确认具体阻塞阶段，也不能将以下改动认定为已经解决该手机的根因。

- 听读服务同时声明并注册 `mediaPlayback` 和 `specialUse`（Android 14 以下只注册媒体播放类型），添加普通的媒体前台服务权限。只有真实前台注册成功才开放播报调度，注册失败保留明确提示。
- 建立系统 MediaSession，通知只显示固定听读标题，不展示消息正文；系统播放/暂停/停止控制与应用内会话一致。任务状态对应缓冲、播放、暂停和停止；空闲时释放焦点及任务唤醒锁，不播放静音音轨保活。原有静音路由确认仅限每段开头的短暂准备阶段，不是全天循环。
- 在已注册的后台音频会话中预绑定当前系统 TTS 引擎。初始化、中文离线声音选择、合成启动、完成及超时各自可诊断；不依赖 Activity 的界面收集器来执行。
- 播放前焦点拒绝、延迟或丢失，使用同一份合成文件，在 1、3、8 秒后最多重试三次。每次延迟焦点最多等待 2 秒；不重新请求云端语音。耗尽只挂起当前批次，不把整条队列一起改为手动补读。
- 已经出声后丢失焦点不自动重播；断连、通话、用户暂停、清空或撤销授权仍使正在等待的任务失效。实际路由不明确时拒绝播放。蓝牙 SCO 通话配置单独消失不再被误认为媒体耳机断开，A2DP/BLE 实际媒体输出检查仍保留。
- 监听断开后请求重连，运行中的服务最多每 30 秒再请求一次。监听恢复时重收当前会话开始后发出的活动通知，沿用原去重规则，不读取会话开始前的通知。

## 诊断方式与隐私

首页下方“后台与息屏听读”提供“复制后台诊断”。先复现后台不读，再回应用复制，可以比较 `UI_HIDDEN → NOTICE_RECEIVED → NOTICE_STORED → TTS_BEGIN → TTS_DONE → FOCUS_REQUEST / FOCUS_RESULT → PLAYER_PREPARED → ROUTE_CONFIRMED → PLAY_DONE` 的时间和缺失阶段。没有出声时不要把 `TTS_DONE` 当作播放成功，只有实际耳机确认后才记录 `ROUTE_CONFIRMED`。

事件包含墙钟与开机计时、内部数字 ID、进程重要性、实际注册的前台服务类型、屏幕与休眠状态、电池优化豁免状态、固定阻塞原因；导出头还包含版本、机型、Android 版本、默认 TTS 引擎包名。调用入口不接受正文或任意错误文本；不保存联系人、通知正文、密钥或音频。

私有设置最多保存 200 条，启动、追加和导出时去掉超过 24 小时的记录。应用不运行时不保证文件准点物理清理。删除全部本地数据会清除已有诊断和暂停设置，之后产生的新状态事件仍会记录。导出由用户主动复制到剪贴板，不自动上传。

## 验证分层

- 队列测试使用模拟输出验证通知触发、去重、连续到达、重试保留同一音频文件，以及清空后不再播放。
- 焦点测试直接调用 Android AudioManager，通过真实媒体前台服务验证前台基线、回桌面、切到系统设置和息屏状态下申请焦点；同时检查实际服务类型与 MediaSession 暂停/恢复。测试不向模拟器扬声器播放通知。
- TTS 测试使用仅存在于仪器测试 APK 的引擎，通过真实 Android TextToSpeech 服务绑定、Binder 回调和 WAV 文件输出，覆盖前台、回桌面、系统设置、立即息屏、息屏静置 10 秒。该引擎产生测试 PCM，不代表手机已安装引擎的中文声音验证，更不代表实际耳机出声。
- 另有默认系统引擎的完整集成测试：实际通知监听 → Room → 默认中文 TTS 合成 → Android 音频焦点 → 消费 WAV 文件，在前台、桌面、系统设置、立即锁屏和锁屏静置 10 秒五种情况下逐条完成，均不打开听讯触发。此模拟器实际绑定 `com.google.android.tts`；只将最终耳机输出替换为模拟消费者，没有替换 TTS 或焦点申请。测试固定中文，不请求 MiniMax 或 OpenAI。
- 单元测试覆盖 1/3/8 秒重试、耗尽、播放前与播放中焦点丢失的区别、安全条件变化、等待取消及普通错误不被吞掉。诊断测试覆盖 200 条上限、24 小时过期、持久化和受限导出字段。

2026-10-18：最终全量验证通过 49 项单元测试、Android 15 / API 35 模拟器 19 项仪器测试；Debug 和 Release Lint 无错误，26 项提示为依赖版本、KTX 和 KSP 建议。签名 release 构建、0.1.3 → 0.1.4 覆盖升级和冷启动通过。versionCode 5，Android 11 起支持，targetSdk 36；签名 SHA-256 与旧版一致：`7cff9843bd8ac504cb1c54c7ca6163449cc7e0f74f652b721c0f4c2e54eff356`。测试引擎不在 release 清单中。报告与签名证据位于 `results/0.1.4/`。

模拟器未显式配置 `tts_default_synth`，系统自动选择已安装引擎；该设置为空不代表没有引擎。绑定日志与测试中的实际中文声音、WAV 输出检查共同证明默认引擎调用完成。仪器测试不覆盖长期 Doze、真实手机引擎的厂商策略或实机扬声器/耳机输出。

## 红米实机验收：待验证

1. 同签名覆盖安装，沿用原应用选择、MiniMax、OpenAI 兼容接口及密钥；保持云端授权原状态。首页选“即时朗读＋系统机读”，开启会话并试听。
2. 分别在回桌面、切换其他应用、立即锁屏和锁屏静置数分钟后，由另一设备发送新的微信消息；记录通知出现与实际出声时间，不通过打开听讯触发。
3. 播放音乐时接收新消息；来电、主动暂停和清空应停止。眼镜断连必须立即停止且不外放；重连后的旧积压需用户确认。
4. 若失败，复现后复制后台诊断，确认是通知没有送达、TTS 没完成、焦点失败，还是路由确认失败，再处理对应阶段。不要仅凭常驻通知存在判定进程一直在执行。

强行停止、重启后仍需用户重新开启会话。没有增加全天唤醒锁、无障碍权限或自动开启云端授权。深度 Doze、HyperOS 后台冻结、真实系统 TTS 及蓝牙输出均须实机复测。

实现依据：[Android 后台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[音频焦点规范](https://developer.android.com/media/optimize/audio-focus)。
