# 0.1.2：OpenAI 兼容摘要与语音

摘要和语音分别提供“MiniMax / OpenAI 兼容接口”选择，可混搭。首页发声方式改为“系统机读 / AI 合成语音”，实际云端提供商以设置中的语音接口类型为准。0.1.1 的蓝牙路由修复保留。

## 配置步骤

1. 打开设置，选择摘要或语音的接口类型为“OpenAI 兼容接口”。
2. 填写服务商的 HTTPS Base URL、模型、Key；语音另填音色。先保存，再开启对应的云端授权。
3. 摘要可直接做固定文字连接测试；语音需连接耳机并开启会话后做连接测试和试听。
4. 语音测试通过后，在首页选择“AI 合成语音”；摘要授权及配置完成后，可选择 AI 摘要或混合模式。

| 参数 | 摘要 | 语音 |
| --- | --- | --- |
| 默认 Base URL | https://api.openai.com/v1 | https://api.openai.com/v1 |
| 端点 | /chat/completions | /audio/speech |
| 模型 | 用户填写服务商的文本模型名 | 预填 gpt-4o-mini-tts，可改 |
| 音色 | 不适用 | 预填 alloy，可改 |
| 返回值 | choices[0].message.content 内的摘要 JSON | MP3 二进制 |

默认 Base URL 和语音模型是标准协议示例，不代表已内置可用账号、免费额度或有效密钥。第三方服务应使用其自身模型和 voice 名称。

摘要支持 `max_tokens`、`max_completion_tokens` 或省略长度参数，不发送 MiniMax 专用字段；长度参数不会在错误后自动切换重试。摘要仍要求返回 `important` 和 `summary`，空结果、思考内容或不符合约定的响应不会直接朗读。

语音请求携带 `model/input/voice/response_format/speed`，只接收有 MP3 头特征的二进制。JSON 错误、HTML 登录页、空音频或超限音频不会被当成声音播放。语音超时、取消、请求限额与系统机读回退沿用原行为。

## 升级、授权与保留

- 沿用原包名与签名，versionCode 3，可覆盖旧版本。Room 数据库格式不变。
- 旧设置没有新提供商字段时默认仍为 MiniMax，原地址、模型、密钥、授权和已通过的语音测试状态按原配置读取。
- 通用摘要、通用语音、MiniMax 摘要、MiniMax 语音分别保存密钥。不会把旧 Key 自动发给新服务商。
- 切换接口类型或修改服务地址后，需要重新授权；语音还需要重新测试。修改模型或音色也会使语音测试状态失效。
- 清空全部本地数据会删除四项密钥；切换提供商不重置当天摘要/语音调用计数。

## 验证范围

单元测试通过 42 项，其中新增 12 项验证通用路径补全、完整端点、请求字段、长度参数选择、MP3 返回、错误响应、鉴权、禁止重定向转发 Key、超时取消、授权与密钥分类。

Debug / Release Lint 和签名 release 构建通过。Android 15 模拟器的 11 项设备测试全部通过，包括设置页切换为通用接口、四组密钥加密保存与重新加载、旧版配置没有提供商字段时保留原配置，以及切换服务后撤销对应授权。签名指纹与 0.1.1 一致。

未提供真实接口密钥，尚未实测 OpenAI 或第三方的付费调用；手机上应先运行连接测试。证据保存于 `results/0.1.2/`，此前版本的记录继续保留。

接口依据：已查阅 [官方 Chat Completions 规范](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 与 [官方 Speech 规范](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create)。
