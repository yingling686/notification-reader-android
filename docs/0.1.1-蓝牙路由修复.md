# 听讯 0.1.1：蓝牙路由确认修复

用户环境：红米 K90 Pro Max、小米 AI 眼镜，其他应用音频通过眼镜正常播放；听讯 0.1.0 提示“无法确认实际耳机输出，已暂缓”。尚未连接该实机，不能把代码修复视为该设备已验收。

## 修改

- 不再选择枚举列表中的第一个蓝牙端口。区分 A2DP 媒体、LE Audio 耳机和 SCO 通话端口；媒体播报不使用仅供通话的 SCO 端口。有线、USB 和助听设备仍受支持。
- 不再要求实际路由端口 ID 与首选端口 ID 完全相同。首选设备只是系统路由请求；实际输出全部为可用的耳机媒体类型时，才允许解除静音。
- 路由等待从约 0.5 秒增加到 3 秒。等待时循环静音播放，避免较短试听在耳机就绪前结束；确认路由后先回到开头，再开始发声。
- Android 16 使用全部实际输出设备检查，混合扬声器与耳机的路由仍拒绝发声。Android 11～15 使用系统返回的实际单路输出。
- 保留播放中路由变化、耳机断开、通话及音频焦点丢失时的停止逻辑。未知路由或扬声器输出不会被放行。
- 首页新增“查看耳机输出检测”，显示检测到的媒体通道、端口及最近实际输出，不包含通知内容或密钥。
- 版本号提升为 0.1.1 / versionCode 2，沿用原签名，可覆盖 0.1.0。

官方依据：[AudioRouting](https://developer.android.com/reference/android/media/AudioRouting) 区分首选设备和实际输出，且实际路由只能在播放时查询。

## 验证

- 30 项单元测试通过：原有 23 项，加 7 项媒体路由回归测试。
- 新增测试覆盖 SCO 先被枚举时选择 A2DP、仅通话通道拒绝播报、实际耳机端口 ID 与首选不同仍可确认、扬声器/未知/混合输出拒绝、断连及路由改变停止、有线与 BLE 耳机选择。
- Debug / Release Lint 和签名 release 构建通过。
- 签名指纹与 0.1.0 一致；已在 Android 15 模拟器上先安装 0.1.0，再通过 `install -r` 覆盖为 0.1.1，安装和冷启动成功。
- 本版本没有真实蓝牙硬件测试，也没有真实云端调用；0.1.0 的设备套件结果作为历史记录保留。

## 更新后验证

1. 直接覆盖安装“听讯-0.1.1.apk”。
2. 连接小米 AI 眼镜，在手机媒体输出中选中眼镜，开启听读，然后点击“试听”。
3. 如仍暂缓，点击首页“查看耳机输出检测”，反馈完整检测文字；它会显示系统是否只暴露通话通道、没有返回路由，或实际仍报告扬声器。
4. 能正常试听后，再检查播放中断开眼镜会立即停止、重新连接不自动补读旧消息。
